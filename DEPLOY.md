# Публикация проекта

Схема: сайт на **Vercel**, API и сервис оценки цены на **Render**, база и хранилище фото в **Supabase** (уже работают). Всё бесплатно. Секреты вводятся только в панелях сервисов, в git они не попадают.

Нужен репозиторий на GitHub (он уже есть) и вход в Render и Vercel через GitHub.

## 1. Render: API и сервис оценки

1. Откройте render.com и войдите через GitHub. Разрешите доступ к репозиторию `TashHome`.
2. **New → Blueprint**, выберите репозиторий. Render прочитает файл `render.yaml` и создаст два сервиса: `tashhome-api` и `tashhome-ml`.
3. Render спросит значения переменных `tashhome-api`. Берите их из своего файла `.env`:

| Переменная | Откуда |
|---|---|
| `SUPABASE_URL` | как в `.env` |
| `SUPABASE_SERVICE_ROLE_KEY` | секретный ключ из `.env` |
| `GEMINI_API_KEY` | как в `.env` |
| `TELEGRAM_BOT_TOKEN` | как в `.env` |
| `TELEGRAM_MANAGERS_CHAT_ID` | как в `.env` |
| `ML_SERVICE_URL`, `WEB_APP_URL`, `TELEGRAM_WEBHOOK_URL` | пока впишите `https://example.com`, настоящие значения будут на шаге 3 |

4. Дождитесь, пока оба сервиса станут **Live** (первая сборка 5–10 минут). Запишите их адреса: `https://tashhome-api.onrender.com` и `https://tashhome-ml.onrender.com` (имена могут отличаться).
5. Проверка: откройте `<адрес API>/api/health`, должно быть `{"status":"ok"}`, и `<адрес ML>/health`, должно быть `model_loaded: true`.

## 2. Vercel: сайт

1. Откройте vercel.com, войдите через GitHub, **Add New → Project**, выберите репозиторий.
2. **Root Directory**: `web`. Framework определится сам (Vite).
3. **Environment Variables**:
   - `VITE_API_URL` = `<адрес API>/api` (например `https://tashhome-api.onrender.com/api`)
   - `VITE_SUPABASE_URL` = как в `.env`
   - `VITE_SUPABASE_ANON_KEY` = публичный ключ (`sb_publishable_…`) из `.env`
4. **Deploy**. Запишите адрес сайта, например `https://tashhome.vercel.app`.

## 3. Связать части

В Render откройте `tashhome-api` → **Environment** и исправьте три переменные:

- `ML_SERVICE_URL` = адрес сервиса оценки (без слеша в конце)
- `WEB_APP_URL` = адрес сайта на Vercel (без слеша в конце). Это разрешает сайту обращаться к API и включает кнопку Mini App в боте.
- `TELEGRAM_WEBHOOK_URL` = `<адрес API>/api/telegram/webhook`

Сервис перезапустится сам. В логах (Logs) должна появиться строка «Telegram-бот запущен (webhook)».

## 4. Проверка

- Сайт открывается, каталог показывает дома, чат ассистента отвечает.
- Бот `@tashhomeebot` отвечает, у карточек домов появились фото.
- Рядом с полем ввода у бота есть кнопка меню **TashHome**: она открывает сайт как Mini App.
- Заявка с сайта приходит в группу менеджеров.
- Вход в админку `<адрес сайта>/admin/login` работает.

## Важно знать

- **Бесплатный Render засыпает** через 15 минут без запросов, первое обращение после этого занимает до минуты. Перед показом откройте сайт и бота за пару минут. Можно настроить бесплатный пинг на uptimerobot.com раз в 5 минут по адресу `<адрес API>/api/health`.
- **Не запускайте локальный сервер с токеном бота, пока работает опубликованный.** Локальный сервер переключит бота с вебхука на опрос, и опубликованная версия перестанет получать сообщения. Для разработки лучше создать второго бота в @BotFather и положить его токен в локальный `.env`.
- Файл `.env` никому не отправляйте и не загружайте в репозиторий: он в `.gitignore`.
- Вход через Google (когда будете подключать): добавьте адрес сайта в **Supabase → Authentication → URL Configuration → Redirect URLs** как `https://<адрес сайта>/**`.
