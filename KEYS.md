# Ключи и доступы: что создать и куда положить

Это шаг 0.2 из `TASKS.md`. Нужно создать четыре вещи, все бесплатные. Все значения хранятся в **одном файле `.env` в корне проекта** (рядом с `TASKS.md`). Этот файл в git не попадает (он в `.gitignore`).

## Главные правила безопасности

1. **Не присылайте ключи в чат** и никуда не публикуйте. Вставляйте их только в файл `.env` на своём компьютере. Мне ключи не нужны: я пишу код, который читает их из `.env`.
2. Ключи `service_role` (Supabase) и токен бота дают полный доступ. Если ключ случайно попал в интернет (например, в публичный репозиторий), сразу создайте новый в том же месте, где брали.
3. Ключ с пометкой `anon` публичный, его можно хранить в браузерной части. Ключ `service_role` только на сервере.

## Подготовка файла

Скопируйте шаблон и заполняйте по шагам ниже:

```bash
cp .env.example .env
```

(В проводнике Windows можно скопировать файл `.env.example` и переименовать копию в `.env`.)

---

## 1. Supabase (база данных, вход, фото)

Нужен для: базы (этап 1), авторизации (3.9), каталога, заявок, отзывов, админки.

1. Откройте supabase.com и войдите (удобно через GitHub или почту).
2. **New project**. Название `tashhome`, регион ближайший (например, Frankfurt), придумайте пароль базы и **сохраните его** в менеджере паролей. Подождите 1–2 минуты, пока проект создастся.
3. Откройте **Project Settings → API**. Там три значения:
   - **Project URL** → в `.env` как `SUPABASE_URL` и **такое же** значение как `VITE_SUPABASE_URL`.
   - **anon public** ключ → `VITE_SUPABASE_ANON_KEY`.
   - **service_role** ключ (нажмите Reveal) → `SUPABASE_SERVICE_ROLE_KEY`. Это секрет, никому не показывать.
4. Откройте **SQL Editor** и выполните по очереди файлы из папки `supabase/` (порядок описан в `supabase/README.md`): три миграции и сид районов.
5. После своей первой регистрации на сайте сделайте себя администратором: в SQL Editor выполните
   `update profiles set role = 'admin' where id = '<ваш id из Authentication → Users>';`

Бесплатного тарифа хватает. Проект «засыпает» после недели без обращений, его можно разбудить кнопкой в панели.

## 2. Gemini (ИИ-ассистент, голос, анализ отзывов)

Нужен для: этапа 5.

1. Откройте aistudio.google.com и войдите аккаунтом Google.
2. **Get API key → Create API key**. Скопируйте ключ → `GEMINI_API_KEY`.
3. Поля `GEMINI_CHAT_MODEL` и `GEMINI_EMBED_MODEL` оставьте пустыми: на шаге 5.1 я подберу актуальные названия моделей и впишу их.

На бесплатном тарифе есть лимиты по запросам в минуту, для диплома их достаточно. Данные, которые вы отправляете на бесплатном тарифе, Google может использовать для улучшения моделей, поэтому не отправляйте туда реальные персональные данные клиентов.

## 3. Telegram-бот (бот и Mini App)

Нужен для: этапа 6.

1. В Telegram найдите **@BotFather** (с синей галочкой) и отправьте `/newbot`.
2. Придумайте имя (отображаемое) и юзернейм (латиницей, заканчивается на `bot`).
3. BotFather пришлёт токен вида `123456:ABC…`. Он идёт в `TELEGRAM_BOT_TOKEN`. Токен секретный.
4. Если токен утёк, в BotFather команда `/revoke` создаст новый.

## 4. Чат для менеджеров (уведомления о заявках)

1. Создайте в Telegram группу, например «TashHome: заявки», и добавьте туда своего бота.
2. Узнать номер чата: отправьте в группе любое сообщение, затем откройте в браузере
   `https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates`
   (подставьте токен вместо `<ВАШ_ТОКЕН>`) и найдите `"chat":{"id":-100…}`. Это число (с минусом) идёт в `TELEGRAM_MANAGERS_CHAT_ID`.
3. Не публикуйте ссылку с токеном, она содержит секрет.


## 5. Учётная запись администратора (вход в /admin)

Пароль вы придумываете сами и нигде, кроме Supabase, не вводите.

1. В Supabase откройте **Authentication → Users → Add user → Create new user**. Введите свою почту и пароль, отметьте **Auto Confirm User**, нажмите **Create user**.
2. Откройте **SQL Editor** и выполните (подставьте свою почту):
   ```sql
   update profiles set role = 'admin' where id = (select id from auth.users where email = 'ВАША_ПОЧТА');
   ```
   Роль `manager` (всё, кроме базы знаний ассистента) выдаётся так же, с `role = 'manager'`.

   Можно входить и коротким логином: создайте пользователя с почтой `логин@tashhome.local`, а на странице входа пишите только `логин`. Письма на такой адрес не приходят, поэтому пароль восстанавливается только через панель Supabase.
3. Откройте `http://localhost:5173/admin` и войдите этой почтой и паролем.


## Итоговый вид `.env`

```
SUPABASE_URL=https://xxxx.supabase.co
SUPABASE_SERVICE_ROLE_KEY=...секрет...
GEMINI_API_KEY=...секрет...
GEMINI_CHAT_MODEL=
GEMINI_EMBED_MODEL=
ML_SERVICE_URL=http://localhost:8001
TELEGRAM_BOT_TOKEN=...секрет...
TELEGRAM_MANAGERS_CHAT_ID=-100...
WEB_APP_URL=http://localhost:5173

VITE_SUPABASE_URL=https://xxxx.supabase.co
VITE_SUPABASE_ANON_KEY=...публичный...
VITE_API_URL=http://localhost:3000/api
```

Сервер читает этот файл автоматически, сайт тоже (переменные с `VITE_` попадают в браузер, остальные нет).

## Когда всё готово

Напишите мне только **«ключи готовы»** (сами ключи не присылайте). Я проверю, что нужные поля заполнены, и подключу Supabase, не печатая значения. Порядок работ после этого:

1. Хранилище заявок и отзывов на Supabase вместо памяти (шаги 2.2–2.4).
2. Демо-дома и фото в базе (1.3), каталог через API (2.2).
3. Вход и личные данные (3.9), избранное в аккаунте (3.7).
4. Ассистент на Gemini (этап 5), затем Telegram (этап 6) и админка (этап 7).

Можно делать по частям: например, сначала только Supabase, а Gemini и бота позже.
