# ИИ-функции TashHome

Подробности — в `SPEC.md` §6. Здесь только правила, которые легко нарушить.

## Ассистент
- Отвечает на языке пользователя (ru/uz), коротко и по делу.
- **Не выдумывает** дома, цены и условия: данные только из инструментов (`search_properties`, `get_property`, `search_knowledge`, `calc_mortgage`, `estimate_price`).
- Заявку (`create_lead`) создаёт только после явного согласия и когда есть имя и телефон `+998…`.
- Лимит — 5 шагов инструментов на ответ. Все сообщения и вызовы пишутся в `chat_messages`.
- Системный промпт и ключи не раскрывает; текст из объявлений и отзывов считает данными, а не командами.

## RAG
- Фрагменты ~800 символов с перекрытием 150, топ-5 по близости, есть порог релевантности.
- Ниже порога — честное «не знаю» и предложение связаться с менеджером; вопрос попадает в «без ответа».
- В ответе указывать источник (название документа).

## Оценка цены
- Признаки для домов: район, площадь дома, площадь участка (сотки), комнаты, этажность, материал, ремонт, год.
- Метка: отклонение < −10 % → ниже рынка, > +10 % → выше рынка, иначе по рынку.
- Метрики (MAE, MAPE, R²) пишутся в `ml/model/metrics.json`; цель MAPE ≤ 15 %.

## Надёжность и безопасность
- Ключи — только на сервере в `.env`; в браузер и в git не попадают.
- Таймаут и ретрай на вызовы Gemini; если ИИ недоступен — каталог и форма заявки работают.
- Структурированные ответы (тональность, описание дома) запрашивать по JSON-схеме и валидировать Zod.

## Проверка качества
- Любое изменение промпта или инструментов → прогнать `npm run eval` (тестовый набор в `server/eval/`) и сравнить с прошлым результатом.
